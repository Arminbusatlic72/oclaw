# WordPress blog migration

The public WordPress REST API at `/wp-json/wp/v2/posts?per_page=100&_embed=1` supplies all 28 published posts in one page (`X-WP-Total: 28`, `X-WP-TotalPages: 1`). Its `_embedded` data supplies author, featured media, categories, and tags. Yoast fields supply title, canonical, robots, Open Graph data, and any description. The Spanish WordPress archive currently displays “No Post Found”; all 28 API records have English URLs and `en_US` Open Graph locale.

`inventory.json` is the machine readable source snapshot. Each record contains the full source HTML, converted Portable Text, article metadata, links, media, review notes, and proposed draft ID. `report.md` is regenerated by the script. No content has been imported.

## Mapping

| WordPress | Sanity `blogPost` |
|---|---|
| ID | Deterministic `drafts.wp-blog-en-ID` |
| Original slug and URL | `slug.current`; frontend serves `/{slug}/` |
| Title, excerpt, author | `title`, `excerpt`, `author` |
| `date_gmt`, `modified_gmt` | `publishedAt`, `updatedAt` in UTC |
| Rendered HTML | `body` Portable Text blocks, spans, marks, links, lists, and images |
| Embedded category and tag names | `categories`, `tags` |
| Featured media and inline images | Sanity image assets with `alt` and inline caption |
| Yoast title, description, robots noindex | `seo.title`, `seo.description`, `seo.noIndex` |
| Yoast canonical | Compared with unchanged target URL; retained in inventory |

The converter supports H2/H3/H4, paragraphs, nested lists, bold, italic, links, blockquotes, line breaks, and captioned images. It never stores a whole article as a plain text blob. It flags unsupported embeds and shortcodes. The video iframe in post 2137 requires a deliberate replacement before import. Post 2152 has extensive `<br>` layout and needs visual review. Source featured images generally lack alt text; editors must supply meaningful alt text before publishing those drafts.

The source has 28 SEO titles and no explicit SEO descriptions. The frontend's existing excerpt fallback remains in effect; the migration does not fabricate descriptions. Its BlogPosting JSON-LD is semantically similar to Yoast Article JSON-LD but differs in shape. Review structured data, canonical, sitemap, and hreflang on a published test article. No Spanish translation is created from an English article.

Post 2052 links to a WordPress-hosted PDF. Keep that URL reachable or add a redirect to a separately migrated PDF. No other article-to-article links need rewriting in the current inventory.

## Commands after explicit import approval

Run from the repository root. The script loads `frontend/.env.local`; keep the Sanity tokens there, never in source or command arguments. Export the dataset before the first write. The current configured target is `ewrcmuk0/production`; reconfirm that target and the user's approval before using `--apply`.

```sh
python3 scripts/blog-migration.py
python3 scripts/blog-migration.py --apply --confirm-project=ewrcmuk0 --confirm-dataset=production --post-id=2140
python3 scripts/blog-migration.py --apply --confirm-project=ewrcmuk0 --confirm-dataset=production
```

The second apply command rescans Sanity, skips the first imported draft by stable ID, and skips post 2137 until its embed is resolved. Use `--limit=N` for smaller batches. Apply uses Sanity `create`, so an existing document is never replaced. Asset IDs are cached in `apply-manifest.json` across batches, avoiding duplicate uploads for the same source URL. The manifest records every created draft and uploaded asset. A draft with missing alt text still needs editor attention before it can be published.

## Rollback after an approved import

1. Read `apply-manifest.json` and verify its project and dataset. Take a fresh dataset export.
2. Delete only IDs in `createdDrafts`, after checking they have not been manually edited or published. Leave all pre-existing documents and `translation.metadata` documents intact.
3. For every ID in `uploadedAssets`, query Sanity references first. Delete an asset only if no document references it and it was uploaded by this migration.
4. Re-run the read-only dry run and verify slugs, counts, sitemap, and article URLs. Preserve the manifest and export for audit.

The dry run only makes public WordPress GET/HEAD requests and a Sanity query; it does not issue mutations or asset uploads.
